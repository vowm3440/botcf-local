# BotCF 本地控制台

以 BotCF(botcf.com)为远端账户/分组/模型/计费中心的本地 AI 工作台:
浏览器或桌面窗口打开即用,凭据只存在本机加密库中,OMP 执行引擎可独立热更新。

## 开始之前(注意事项)

**1. 本项目不附带任何模型额度,凭据要你自己准备。** 两种任选其一:BotCF 账号(账号密码或
管理 Token),或者**第三方提供商模式**——自填 Base URL + API Key + 模型列表,任何
OpenAI / Anthropic 兼容端点都可以。没��凭据的话,界面能打开,但发不出任何一条消息。

**2. 首次启动会联网下载 AI 执行引擎(OMP),打包好的 exe 里不含它。**
默认从 GitHub 的 `can1357/oh-my-pi` 拉取 Release。**拿不到也能用,但会降级为「直连模式」**:

| | 直连模式(没有 OMP) | 完整模式(装好 OMP) |
|---|---|---|
| 对话、思考过程、模型路由 | ✅ | ✅ |
| 工具调用、读写你的文件 | ❌ | ✅ |
| 变更文件列表、内联差异、AI 修改审查 | ❌ | ✅ |

所以如果你下载了 exe、打开之后发现「AI 只会聊天不会改代码」,**那不是 exe 坏了**——是没能
装上 OMP。常见原因:断网、GitHub 不可达、代理没配。顶栏 ⚙ →「运行时」会显示当前状态与失败
原因,配好网络后点「立即检查更新」即可。

**3. 端口 `127.0.0.1:7788` 与 `7789` 是固定的。** 被占用(例如同时开着开发服务器或另一份
拷贝)时启动会直接失败并提示。

**4. exe 没有代码签名**,Windows SmartScreen 会拦一次——处理方式见下面「Windows SmartScreen」。

**5. 只监听回环地址。** 所有服务都绑 `127.0.0.1`,不对局域网暴露;凭据以 AES-256-GCM 加密
存在 `%APPDATA%/botcf-desktop/data`(桌面版)。**卸载不会删除这个目录**,要彻底清除请手动删。

**6. 自行开发或打包需要 Node 22+**;直接用打包好的 exe 则不需要装任何东西。

## 功能

- **BotCF 账户接入**:账号密码或管理 Token 登录;余额/用量实时同步(按站点 `quota_per_unit` 换算美元)
- **第三方提供商模式**:登录页第三种方式——自填 Base URL、API Key 与模型列表即可使用任意 OpenAI/Anthropic 兼容端点(claude 开头走 Messages,其余走 Chat Completions);Key 同样只存本机加密库、由凭据代理注入;顶栏显示端点地址、模型与思考等级选择,对话/工具/差异视图全部一致
- **分组专用 Key**:为所选分组自动查找/创建 `omp-local-<设备ID>-<分组>` 专用 Key,绝不改动已有共享 Key
- **动态模型目录**:分组聚合自默认分组、已有 Key、`/api/user/self/groups` 与公开 pricing 接口——未建过 Key 的分组同样可见;模型优先按 pricing 的 enable_groups 精确过滤,缺数据时回退家族启发式;图像/视频分组自动隐藏;分组每 5 分钟与网站自动同步,「立即同步」即时刷新;`/api/groups/debug` 可诊断各来源实际返回
- **诚实的上下文能力库**:每条「分组+模型+接口」路由独立记录 declared/verified/effective 三层上下文与置信度(已验证/文档确认/推断),上游报 context 超限自动降级
- **多接口路由**:codex 分组走 OpenAI Responses,claude 分组走 Anthropic Messages,其余走 Chat Completions;所有模型统一提供思考等级 low/medium/high/xhigh/max(由 OMP set_thinking_level 应用;直连 Responses 模式将 xhigh/max 收敛为 high)
- **凭据代理**:OMP/前端永远只接触 `127.0.0.1:7789` 本地代理,真实 Key 由代理注入;日志全量脱敏
- **模型健康状态**:选好分组+模型后,顶栏用 10 根状态柱加一个成功率呈现当前路由的健康度(悬停给出窗口、样本量、首字延迟与图例),完整明细在顶栏 ⚙ 的「模型状态」里两行列全——**网站**直接使用 botcf.com/pricing 的分组状态资源、10 个一分钟状态柱、首字延迟和成功率,并按官网规则每 15 秒刷新(绿=低于官网故障阈值/紫=达到阈值/红=全部失败/灰=无调用);**本机实测**保留近 8 小时逐 10 分钟的真实请求观测(绿=全部成功/紫=部分失败/红=全部失败/灰=无请求)
- **多根工作区(Multi-root Workspace)**:工作区可同时打开多个项目目录(上限 8 个),文件面板把它们并列为顶层节点,编辑器、差异视图、变更文件列表统一使用 `<目录名>/<相对路径>` 这一种路径形式,跨目录也不会歧义;其中一个目录是**主目录**(= AI 进程的 cwd),可随时在文件面板里「设为主」切换(会重启 OMP 并停预览),增删非主目录不打断正在进行的对话;旧版单目录设置在升级后自动迁移为单根工作区
- **变更文件可见**:每轮回答结束展示 OMP 修改过的文件;活动栏的「资源」视图浏览整个工作区(变更标记、每行 `+新增 −删除` 计数、每轮自动刷新),点击任意文件在编辑器区打开查看器,变更文件附带三种读法:可编辑的**内容**、就地显示改动的**内联**、工具原文**差异**
- **多标签编辑器**:多个文件以标签页并排打开(不再互相顶掉),AI 每改一个文件就自动补一个标签;标签可拖拽排序、中键/✕ 关闭、`仅保留当前`/`全部关闭`,未保存标签显示 ● 并免于被淘汰,AI 改过的标签带 `+N −M`;标签顺序与**当前活动标签**持久化,刷新后原样恢复;`Ctrl+Alt+←/→` 切换标签、`Alt+1…9` 直达第 n 个;未保存草稿存在内存缓存中,重挂载不会丢失
- **活动文件自动跟随 + 内联差异 + AI 编辑追踪**:资源管理器跟着编辑器走——切换标签或 AI 改动文件时自动展开各级目录、滚动到该行并高亮(「跟随」开关持久化,关掉后仍可点「定位」手动定位);编辑器左边距按 AI 改过的行画变更条(新增绿 / 改写蓝 / 删除红楔),点击变更条即跳到内联视图;`Alt+F5`(加 Shift 往回)在各处改动之间跳转;改动的行号**按内容重新对齐**而不是照搬差异里的行号——下一轮改了同一个文件、或你自己敲了几行,标记依然落在正确的位置,真的找不到了就不再标(宁可不画,也不画在没改过的代码上);顶栏文件名旁、资源管理器每行、状态栏都用同一份 `+N −M`
- **可停靠的分割面板工作台(Dock)**:整个界面只有**一种**容器——「面板组」(一组标签共用一条标签栏),面板组之间横向或纵向分割。资源管理器 / 源代码管理 / 运行和任务 / AI 审查 / 项目配置 / 编辑器 / 问题 / 终端 / 预览 / AI 对话都是同一种「部件」,因此**每一个都能拖到任意位置**:拖到某个面板的上下左右边缘就在那里分出一栏,拖到它的标签栏就并成一个标签页,拖到窗口最外侧则新开一整条边栏;拖动时只有一个高亮块在各个落点之间滑动,大小就是松手后的真实大小。分隔条是 1px 细线、7px 可抓区域,拖动 1:1 跟手,方向键微调、双击平分,每个面板都有最小尺寸不会被挤没。任意面板可**最大化**(双击标签栏亦可),标签可拖拽重排、中键关闭;左侧**活动栏**列出全部部件——蓝条=正在看,墨色=已打开但在后台,灰色=已关闭,点当前项收起,任何面板都能从这里找回来,底部「布局」一键恢复默认(可再点一次撤销)。整套排布持久化到 localStorage,旧版固定槽位布局会在升级时按原比例迁移过来。键盘也能停靠:焦点在标签上按 `Alt+Shift+方向键` 即把该面板停靠到窗口那一侧
- **顶栏只留状态**:顶部是固定 44px 的单行栏,按信息的**种类**分区——左边是路由面包屑「分组 › 模型 · 思考等级 · 上下文」(唯一需要主动改的东西,也是唯一的粗体),中间是模型健康脉冲与 OMP 更新进度,右边是余额和一条额度用量细线;更新通道、OMP 仓库、启动/重连、权限档位、主目录、立即同步、退出登录等**配置**全部收进右侧 ⚙ 浮层(按运行时 / 权限 / 工作目录 / 用量 / 模型状态 / 账号分组),⚙ 上的状态灯在运行时空闲、有待更新或出错时才亮。窗口再窄也不换行、不改变高度,只有出错才临时多出一行可关闭的提示
- **看得见的思考与运行过程**:OMP 的思考(thinking)增量单独成流,在对话里以可折叠的「思考中…」块实时显示——模型只思考、还没写出正文时,这里就是你看到的东西,不再是一段空白;上下文压缩、自动重试、备用模型回退、模型/思考等级切换、运行时提示等**终端里会打印的行**也一并回传,以 `·`/`!` 前缀的等宽小字显示;工具输出按终端语义清理(去 ANSI、应用 `\r` 覆盖),看到的就是 PowerShell 里会留在屏幕上的内容
- **输出预算按模型族给足**:每条路由的 `max_output` 由模型族文档值与「不超过上下文窗口 1/4」两个约束共同决定(旧版是所有模型一律 8192)。推理模型会先把输出预算花在思考上,预算太小就会出现「读完文件就停住、正文空白」——那是 `stopReason: length` 截断,不是模型偷懒;真的撞上上限时对话里会明说被截断,并记入诊断中心
- **工具确认 / 完全访问**:顶栏 ⚙ →「权限」两档可选并**始终显示当前档位**(对话输入框里也有一枚状态标签)。`确认模式`= 运行时请求确认时弹窗问你;`完全访问`= 本机自动允许,一轮回答不会中途停下,已自动允许的动作写进对话记录。这只改变「是否弹窗询问」——OMP 的 RPC 协议没有权限开关,文件仍限于工作区目录,其余边界不变
- **命令行式输入框**:整块圆角容器里放着 `›` 提示符、自动增高的 textarea(最多 200px 后内部滚动)与一条页脚——左边是当前模型 · 思考等级 · 权限档位,右边是按键提示与发送/中止按钮;要确认的运行设置就写在你打字的地方。Enter 发送、Shift+Enter 换行,输入法组字期间的 Enter 只上屏候选词,长行不再把整列顶宽
- **沙箱化实时预览**:内置浏览器面板(sandbox iframe)预览工作区里的项目(多根工作区下用面板里的目录选择器指定预览哪一个,一次预览一个),两种引擎——**静态模式**由内置回环服务器托管并递归监听文件改动(仅样式改动时热替换 CSS 保留页面状态,其余整页重载),**命令模式**运行项目自带 dev server(`npm/pnpm/yarn/bun run <script>`,脚本名取自该项目 package.json 白名单)并从输出中嗅探地址,由其原生 HMR 增量更新;面板提供路径栏、刷新、外部打开、手机/平板/桌面宽度预设、dev server 日志与页面运行时报错回传
- **Git 集成(状态 / 差异 / 提交 / 回滚)**:按工作区目录查看分支、上下游领先落后、暂存区与工作区状态;逐文件查看差异(未暂存 / 已暂存 / 相对 HEAD 三种口径,GitHub 风格高亮)、暂存/取消暂存、丢弃未提交修改(新建文件需显式勾选才删除);填一行信息即可提交;两种回滚区分清楚——**撤销上一个提交**把分支指针回退一步并保留改动(已推送时默认拒绝改写历史),**回滚此提交**生成反向提交,冲突时可一键放弃
- **AI 修改审查**:AI 每轮改完的文件进入审查列表,逐个查看差异后决定**接受**(按项目配置自动 `git add`,提交时只包含审查过的内容)或**撤销**(用 git 还原;AI 新建的文件需勾选后才删除),最后按项目模板一次性提交;同一文件再次被改动会自动回到「待审查」,过期的批准不会被沿用;非 git 目录仍可查看 AI 自报差异,并明确提示无法自动撤销
- **统一任务系统(build / run / test)**:任务来自 `.botcf/config.json` 与项目 `package.json` 脚本(按名字归类到构建/运行/测试/检查),运行、停止、实时输出、退出码与耗时都在同一面板;运行始终是显式点击,命令行始终可见;输出里的编译/测试/lint 错误自动解析进诊断中心,同一任务重跑会替换自己上一次的诊断
- **内置终端**:在任意工作区目录里开 shell(Windows 默认 PowerShell,POSIX 跟随登录 shell),输出逐行流式回传并带序号,切面板/刷新页面都能续读同一份记录;命令历史 ↑↓、中断、清屏、多会话切换。管道终端不带 PTY——适合 npm/git/脚本,不支持全屏程序与交互式密码,面板里如实标注
- **错误与诊断中心**:任务输出(tsc / eslint / vitest / rust / esbuild-vite / Node 堆栈)、任务失败、预览与 dev server 报错、被预览页面的运行时异常、AI 工具失败与 OMP 更新回滚,统一汇总为一份按严重程度排序的列表;重复出现的同一问题折叠计数,点击即在编辑器里跳到对应文件行
- **项目级配置**:每个工作区目录一份 `.botcf/config.json`——任务列表(脚本名或显式命令、子目录、环境变量、常驻标记)、预览默认模式与脚本、终端 shell 与环境变量、审查行为与提交信息模板;表单与 JSON 两种编辑方式,保存后回显规范化结果与被拒条目的原因(绝不静默丢弃)
- **OMP Runtime 热更新**:GitHub Releases 自动跟版(快速/稳定/实验三通道)、SHA256 校验、空闲切换、健康检查失败秒级回滚;未安装 OMP 时自动降级为直连模式
- **加密存储**:BotCF 会话与 Key 用 AES-256-GCM 加密落盘,master.key 权限 0600

## 运行方式

### 开发模式

```bash
npm install
npm run dev:server   # 控制服务 127.0.0.1:7788 + 凭据代理 127.0.0.1:7789
npm run dev:web      # Vite 开发服务器(已配置 /api 代理)
```

### 桌面应用(开发)

```bash
npm run desktop      # 构建后以 Electron 窗口运行,需系统 Node 22+
```

### 独立可执行文件(Windows x64)

```bash
npm run dist:desktop # 产出 apps/desktop/release/ 下两个 exe
```

| 产物 | 用法 | 适合 |
|------|------|------|
| `BotCF-Local-v3.0.0-portable.exe` | **双击即用**,不安装、不写注册表、不需要管理员 | 试用、U 盘随身、不想安装 |
| `BotCF-Local-v3.0.0-Setup.exe` | 安装向导(可选安装目录),装完有开始菜单/桌面快捷方式 | 日常长期使用 |

两者内置 Electron 运行时并使用 esbuild 单文件服务端 bundle,**最终用户无需安装 Node**。
两者共用同一个数据目录 `%APPDATA%/botcf-desktop/data`,便携版与安装版之间切换不会丢登录和 Key。
便携版每次启动会先把自身解包到 `%TEMP%`,首次启动比安装版慢几秒(还会被杀软扫一遍),这是便携 exe 的固有代价。
窗口标题带版本号(`BotCF 本地控制台 v3.0.0`),便于区分同时存在的多个版本。
产品图标由 `apps/desktop/build/generate-icon.mjs` 确定性生成到
`apps/desktop/build/icon.ico`,exe、安装器与卸载器共用同一个图标;改动图标改脚本即可
(`npm run icon -w apps/desktop` 可单独重跑)。

`npm run dist:desktop` 走的是 `apps/desktop/build/dist.mjs` 而不是裸的
`electron-builder --win`,因为后者曾经带着默认 Electron 图标"成功"过一次:配置里写着
`build/icon.ico`,但没有任何步骤生成它,electron-builder 只是打印一行
`default Electron icon is used` 就继续走。发布入口因此自己判定四件事——生成图标、校验
容器内确有 256×256 PNG、把那行日志当作失败、**从产物 PE 里读回 RT_ICON 资源**与 `.ico`
载荷逐字节比对(主程序 / Portable / Setup 三个都要匹配)。卸载器的图标由 NSIS 在编译期
写进压缩负载、无法回读,脚本改为断言三个 NSIS 图标槽位都指向生成物,并把"这一项是配置
断言而非资源回读"打印出来。

端口固定 `127.0.0.1:7788`——若该端口已被开发服务器或另一份拷贝占用,启动会提示失败。

#### Windows SmartScreen(未签名可执行文件)

当前 exe 未使用 EV/OV 代码签名证书,首次运行可能显示「Windows 已保护你的电脑」。
仅从项目发布渠道获取,先用 `Get-FileHash -Algorithm SHA256 "<文件路径>"` 校验发布页摘要;
摘要一致时可点击「更多信息」→「仍要运行」。不要关闭 SmartScreen 或修改系统安全策略。
面向公众发布前应为两个 exe 和卸载器配置受信任的 Authenticode 签名。

### Docker

```bash
cd docker
docker compose up -d   # 仅绑定 127.0.0.1:7788
```

容器非 root、`cap_drop: ALL`、只读根文件系统(仅 /data、/tmp 可写)。
项目目录需要显式添加 volume 才会进入容器。
多架构离线产物可用 `docker buildx build --platform linux/amd64,linux/arm64 --output type=oci,dest=botcf-local-multiarch.tar -f docker/Dockerfile .` 构建。

由于根文件系统只读,OMP 的 native addon 必须解压到可写卷:镜像把 `HOME` 设为 `/data/home`,
入口脚本在启动前创建该目录。宿主的 `data` 目录属主必须是 `1001:1001`,否则容器会带着明确的错误信息退出
(而不是 `/health` 正常但 AI 运行时静默不可用)。Alpine 镜像同时安装 `gcompat`,
使没有 musl 资产的 OMP 版本也能加载;`pickReleaseAsset` 在 musl 主机上优先选择 musl 资产。

容器发布验收不能只看 `/health`:必须确认 `GET /api/omp/status` 的 `running:true`、`protocolError:null`,
并在容器内实跑一次带模型路由的对话。

## 多根工作区(Multi-root Workspace)

工作区 = 一组项目目录(root)+ 一个**主目录**。资源管理器顶部的「添加目录」把任意本地目录加入工作区,
每个目录以自己的名字作为顶层节点显示;名字取自目录名,重名自动加 `-2`、`-3` 后缀。

| 操作 | 位置 | 影响 |
|------|------|------|
| 添加目录 | 资源管理器「添加目录」 | 只扩大资源管理器/编辑器/预览能访问的范围,**不重启 OMP**,不打断正在生成的回答 |
| 设为主目录 | 资源管理器中该目录行的「设为主」 | 主目录是 AI 进程的 cwd。OMP 的 cwd 只能在进程启动时指定,因此切换会**停预览并重启 OMP**(会话记录在磁盘上,不会丢) |
| 移除目录 | 资源管理器中该目录行的「✕」 | 只是移出工作区,**不删除磁盘文件**;正在预览该目录时会停预览;移除主目录时主目录顺延到剩下的第一个 |
| 更改主目录 | 顶栏 ⚙ →「工作目录 · 更改主目录」 | 等价于「添加该目录 + 设为主」,其他目录保持打开 |

重启只有一条路径(`omp/runtime.ts`):停进程 → 启动 → RPC 握手 → **重新下发并校验当前路由** → 才算重启成功。
OMP 会在启动时恢复它自己保存的模型,所以少了最后两步,界面显示的分组/模型和 OMP 实际使用的就会分家
(表现为代理返回 409、回答空白)。任何一步失败都不会报告 `restarted:true`,而是带上 `runtimeError`
停掉 OMP 退回直连模式,资源管理器会把原因显示出来。切换主目录、顶栏的显式重启、版本切换后的健康探针都走这里。

### 路径形式

所有面板与文件接口只使用一种路径:**`<目录名>/<相对路径>`**(工作区本身是空字符串)。
无法归属到任何 root 的文件(AI 用绝对路径改了工作区外的文件)保持绝对路径形式,
资源管理器不会为它开标签页——那类文件读不回来,只会显示报错。

- `GET /api/workspace` — 目录列表、主目录 id、目录上限
- `POST /api/workspace/roots` `{path, name?, primary?}` — 加入目录(幂等)
- `POST /api/workspace/roots/remove` `{id}` — 移出目录
- `POST /api/workspace/primary` `{id}` — 切换主目录
- `GET /api/omp/files?path=<目录名>/<相对路径>` — 目录列表;`path` 为空时列出各个 root
- `GET|POST /api/omp/file?path=<目录名>/<相对路径>` — 读取/保存单个文件
- `GET /api/preview/status?root=<id|名字>`、`POST /api/preview/start {root}` — 指定预览哪个目录

### 边界

- 每个请求先按目录名选中 root,再在该 root 内做包含性检查(字符串 + realpath 双重),
  `..` 与符号链接都无法借一个 root 跳到工作区外,也无法跳进另一个 root
- 目录上限 8 个;客户端只能按 id/名字指定已打开的 root,任何接口都不接受由客户端传入的磁盘路径去预览
- **AI 的工作目录仍然只有一个**(主目录)。其他 root 对 AI 是普通的绝对路径,不会自动进入它的上下文;
  需要跨目录改动时,在对话中给出绝对路径。这些改动同样会出现在变更文件列表里(以对应目录名为前缀)
- 目录在磁盘上被删除后不会自动消失,而是标红显示「目录不存在」,由用户决定何时移除
- 升级:旧版单目录设置(`omp.workdir`)在首次启动时自动迁移为单根工作区,不需要重新选目录;
  编辑器标签的本地存储键升到 `botcf.tabs.v2`(路径形式变了,旧标签不再自动恢复)

## 实时预览(Live Preview)

面板区的「预览」标签打开预览。启动始终是显式动作——命令模式会运行项目自己的代码。
多根工作区下,面板里的目录选择器决定预览哪个 root(默认主目录),切换选择会按该目录重新做项目探测。

| 模式 | 何时自动推荐 | 热更新方式 |
|------|--------------|-----------|
| 静态 | 目录里有 `index.html`(或 `public/`、`src/`、`dist/` 下的入口)且没有 dev 脚本 | 内置服务器注入的 SSE 客户端:改 `.css` 只热替换样式表,改其他文件整页重载 |
| 命令 | `package.json` 里存在 `dev`/`start`/`serve`/`preview` 之类脚本 | 项目自带 dev server 的原生 HMR(Vite / Next / webpack-dev-server 等) |

预览页面的安全边界:

- 静态服务器只绑回环,并与控制面共用同一套 Host/Origin 校验(阻断 DNS 重绑定),只接受 GET/HEAD
- 每个请求路径都走被预览目录的包含性检查(字符串 + realpath 双重),符号链接无法把目录外的文件带出来
- iframe 使用 `sandbox`,不授予 `allow-top-navigation`;因为预览运行在**另一个端口**(独立源),`allow-same-origin` 只让被预览页拥有自己的存储,读不到控制台源的数据
- 命令模式只接受该项目 `package.json` 中声明的脚本名(并再按 `[A-Za-z0-9:_.-]` 校验),HTTP 层无法传入任意命令行
- 客户端只能按 id/名字指定**已加入工作区**的目录,不能传路径;切换主目录、移除正在预览的目录、进程收到 SIGINT/SIGTERM 时都会停掉预览与其 dev server 子进程树

Docker 下预览需要固定端口才能被宿主浏览器访问:设置 `PREVIEW_PORT=7790` 并在 compose 里映射
`127.0.0.1:7790:7790`(见 `docker/docker-compose.yml` 中的注释)。

## 工作台布局(VS Code 式)

界面按 VS Code 的槽位划分,每个功能有固定的位置:

| 槽位 | 内容 | 说明 |
|------|------|------|
| 顶栏(最上) | 左:分组 › 模型 · 思考等级 · 上下文;中:模型健康脉冲与 OMP 更新进度;右:余额与额度条、⚙ 设置浮层 | 固定 44px 一行、不换行、不参与工作台的开合;配置(含权限档位)都在 ⚙ 里,出错才临时多一行提示 |
| 活动栏(最左) | 资源 / 源码 / 运行 / 审查 / 配置,底部是「对话」与「日志」 | 点当前项收起主侧边栏;「审查」上带待审查文件数徽标 |
| 主侧边栏 | 资源管理器、源代码管理、运行和任务、AI 修改审查、项目配置 | 宽度可拖,一次显示一个视图 |
| 编辑器区(中间) | 多标签编辑器 + 内容 / 内联 / 差异 三种读法 | 没有打开文件时显示提示与快捷键 |
| 面板区(下方) | 问题 / 终端 / 预览 | 标签切换,可最大化(临时占满编辑器区)、可关闭;「问题」上带错误+警告数徽标 |
| 次侧边栏(右) | AI 对话 | 可隐藏;隐藏时仍保持挂载,流式输出不中断 |
| 状态栏(最底) | 错误/警告数、待审查数、连接模式、本会话 AI 改动、Token 与上下文占用、路由 | 「问题」「审查」「AI 改动」三处可点,直接跳到对应槽位 |

**只有正在显示的视图/标签会挂载**——切走即停止其事件流,不会在后台继续订阅。
这不会丢东西:终端记录、诊断列表与 dev server 都在服务端,重新挂载时回放。
唯二始终挂载的是 AI 对话(流式订阅属于该实例)与编辑器(滚动位置和未保存缓冲),它们用 CSS 隐藏。

侧边栏宽度、面板高度、对话宽度与各槽位的开合状态持久化到 `botcf.workbench.v1`。

所有面板都按**一个工作区目录**工作:客户端只能按 id 或目录名指定**已加入工作区**的目录,
任何接口都不接受由客户端传入的磁盘路径;省略时使用主目录(= AI 的 cwd)。

### 活动文件跟随、内联差异与 AI 编辑追踪

AI 每改一个文件就自动开一个标签,一轮下来可能同时开着八个;这三件事解决的是同一个问题——
**当前看的是哪个文件、AI 到底在这个文件里改了什么、改的地方在哪一行**。

| 能力 | 位置 | 行为 |
|------|------|------|
| 活动文件跟随 | 资源管理器头部「跟随」 | 编辑器换到哪个文件,树就展开各级目录、滚动过去并高亮该行;逐级列目录(每一层的列表才能证明下一层存在),因此深路径要等几帧才滚到位。连续切换时后发起的定位覆盖先前的,不会互相打断。开关持久化在 `botcf.explorer.autoReveal`(默认开) |
| 手动定位 | 资源管理器头部「定位」 | 「跟随」关掉后仍可一次性定位当前文件 |
| 变更条 | 编辑器左边距 | AI 改过的行画一条竖条:新增绿、改写蓝、删除是两行之间的红楔(那一行已经不存在,标它的邻居等于冤枉没改过的代码)。点变更条即跳到内联视图对应位置 |
| 改动间跳转 | `Alt+F5` / `Shift+Alt+F5`,或头部 ↓ ↑ | 在本文件各处 AI 改动之间循环跳转,同一个键可以一直按下去 |
| 内联视图 | 编辑器头部「内联」 | 整份文件里就地显示改动:新增行绿底、被删掉的行以红底留在它原来的位置,未改动的大段折叠成一行「N 行未改动」(点开即全文,超过 4000 行只保留改动附近) |
| 差异视图 | 编辑器头部「差异」 | OMP 工具报告的统一差异原文,GitHub 风格行号栏与词级高亮 |
| `+N −M` | 标签、资源管理器每行、本会话变更列表、状态栏 | 同一份计数,四处显示;状态栏那一项点开资源管理器 |

**行号是重新对齐出来的,不是照搬的。** 差异文本里的行号在写下的那一刻就开始过期:下一轮又改了这个文件、
或者你自己在上面敲了几行,行号就不再指向原来的代码。所以每个改动区块同时记着**它写进去的那几行文本**,
显示前拿这段文本回到当前缓冲区里重新定位——先看原位,再向上下各 400 行内找,找到就跟着挪;
**找不到就不画**(宁可不标,也不把绿条画在 AI 从没碰过的代码上)。多次工具调用拼起来的差异、
没有 `@@` 头的工具差异都按同一套规则处理,只是这时行号只是搜索的起点。头部的 `AI +N −M · k 处`
数的是**当前还能定位到的**那些;有一部分被覆盖时旁边显示 `!`,全部被覆盖时直接说「已被覆盖」。

对齐是靠约定而不是测量:行高是一个常量(`editor/diffPalette.ts`),边距、色带与文本三层共用它,
文本层永不折行(`wrap="off"`)——软折行会让某一行占两行高,它下面所有色带就都指错代码。
色带是每个区块一个元素(不是每行一个),两万行的文件里三处改动就是三个元素;滚动时直接写
`transform`,不经过 React 状态,拖滚动条不会顿。

### Git

| 操作 | 说明 |
|------|------|
| 状态 | 分支 / 上游 / 领先落后、暂存区、工作区、未跟踪、冲突分组显示;子目录被单独加入工作区时,只显示该子树 |
| 差异 | 未暂存(工作区↔暂存区)、已暂存(暂存区↔HEAD)、相对 HEAD(全部未提交改动);未跟踪文件按「全新增」合成差异 |
| 暂存 / 取消暂存 | 单个文件或一次全部;仓库还没有提交时用 `git rm --cached` 取消暂存 |
| 撤销修改 | 丢弃未提交改动(已暂存的先取消暂存再还原);**新建文件默认跳过**,勾选「撤销时删除新建文件」后才删除——git 无法恢复它 |
| 提交 | 提交信息经 stdin 传给 `git commit -F -`(不进 argv,不经 shell);没有暂存内容或存在冲突时明确拒绝;缺少 `user.name/user.email` 时给出可执行的提示 |
| 撤销上一个提交 | `git reset --mixed HEAD~1`,改动全部留在工作区;**已推送**(有上游且未领先)时默认拒绝,提示改用回滚 |
| 回滚此提交 | `git revert --no-edit <hash>` 生成反向提交,不改写历史;冲突时停在冲突状态,可「放弃回滚」(`git revert --abort`) |

边界:每个路径都是**目录内相对路径**,先做包含性检查(字符串 + realpath)再成为 pathspec;
以 `-` 开头、含 NUL/换行、绝对路径、越界路径一律拒绝;单次最多 200 个路径;
git 进程永不经过 shell,禁用凭据/编辑器交互(`GIT_TERMINAL_PROMPT=0`),输出有大小与超时上限。

### AI 修改审查

AI 每轮结束时,服务端把这一轮改动的文件交给审查层(和「本轮变更」用的是同一份数据),
面板据此列出文件 + git 的实时状态 + 一个决定:

- **接受**:标记保留;若项目配置里 `review.stageOnAccept` 为真则同时 `git add`,提交时就只包含审查过的内容
- **撤销**:用 git 还原(未暂存→`git checkout --`,已暂存→先 `reset` 再还原);AI 新建的文件需勾选后才删除
- **提交已接受**:按 `review.commitTemplate`(支持 `{count}`、`{files}`)生成信息,提交后这些文件离开审查列表
- 同一文件再次被 AI 改动 → 自动回到「待审查」;跨多个目录时按目录分别提交

差异优先取 git(相对 HEAD,始终是磁盘现状),没有 git 仓库时回退到 AI 工具自报的差异,
并在面板里说明该目录无法自动撤销。工作区之外的绝对路径文件会标出来,不参与 git 操作。

### 统一任务系统

任务 = `.botcf/config.json` 里显式声明的条目 + `package.json` 脚本自动识别,两者同一套执行、
同一套输出、同一套诊断:

| 来源 | 归类方式 |
|------|----------|
| 项目配置 | 自带 `kind`(build/run/test/lint/custom),可指定脚本名或显式命令、子目录、环境变量、常驻标记 |
| package.json | 按脚本名归类:`build*`→构建、`test*`/`coverage`→测试、`lint*`/`typecheck`/`tsc`→检查、`dev`/`start`/`serve`→运行(常驻) |

同一目录里同一个任务不会并发运行,全局最多 4 个并发执行,保留最近 12 条执行记录;
每条记录带退出码、耗时、问题数与可续读的输出(序号化环形缓冲,切面板不丢日志)。
执行始终是显式点击,面板里始终显示将要运行的完整命令行。

### 内置终端

在所选目录里启动 shell(`powershell -Command -` / `cmd /K` / `bash -s` 之类的「从 stdin 读命令」模式),
输入回显进同一份记录(多个面板看到一致的历史),输出逐行清理 ANSI、应用 `\r` 覆盖并脱敏。
最多 4 个活动会话,退出的会话保留记录便于回看;移除工作区目录、进程退出时都会关闭其中的会话。

**能力边界(面板中如实标注)**:管道终端没有 PTY——`vim`/`top` 这类全屏程序、交互式密码输入不可用;
「中断」向进程组发信号(Windows 上按进程树结束),通常会一并结束会话,再点「新建会话」即可。

### 错误与诊断中心

一份按严重程度排序的问题列表,来源包括:

| 来源 | 内容 |
|------|------|
| 任务 | tsc、eslint(stylish)、esbuild/vite/gcc 风格 `file:line:col`、rust `error[E0382]` + `-->`、vitest `FAIL` 与栈帧、Node 异常 + 首个栈帧;以及任务本身的失败(退出码) |
| 预览 | 预览启动失败、dev server 报错 |
| 页面运行时 | 被预览页面里抛出的异常(经 sandbox postMessage 回传后记录) |
| AI 运行时 | 工具调用失败、**模型调用失败(终止原因为 error 的一轮,带 HTTP 状态)**、输出达到上限被截断、OMP 进程异常退出、运行时重启失败、OMP 更新失败或回滚 |

一轮对话的终止原因有四种,每一种都有用户能看见的结果:正常结束照常收尾;`error` 作为脱敏后的
`[错误]` 追加到回答里并进诊断中心;`length` 给出「被截断」的警告;中止显示 `[已中止]`。
**空白的助手消息永远不是错误的正常表示**——那正是路由不匹配的 409 曾经的样子。

同一问题重复出现会折叠成一条并计数;带位置的条目点击即在编辑器里跳到该行(编辑器会滚动并选中整行)。
任务重跑会替换自己上一次的诊断,可按来源或全部清空;总量有上限,超出时淘汰最久未出现的条目。

### 项目级配置

每个工作区目录一份 `.botcf/config.json`(不存在时使用默认值,可一键创建):

```jsonc
{
  "version": 1,
  "discoverScripts": true,              // 是否自动识别 package.json 脚本
  "tasks": [
    { "name": "类型检查", "kind": "lint", "command": ["npx", "tsc", "--noEmit"], "cwd": "apps/server" },
    { "name": "构建", "kind": "build", "script": "build" }
  ],
  "preview": { "mode": "auto", "script": null },
  "terminal": { "shell": null, "env": { "FORCE_COLOR": "0" } },
  "review": { "stageOnAccept": true, "commitTemplate": "chore: 应用 AI 修改 ({count} 个文件)" }
}
```

这个文件位于项目内部,因此和项目自己的 `package.json` 一样按**不可信输入**处理:

- 命令参数只允许 `[A-Za-z0-9_@:.,=+~/\-]`(不允许空格与 shell 元字符),最多 16 个参数;
  Windows 上运行 `npm.cmd` 之类的 shim 必须经 shell,这个字符集就是为此设的
- `cwd` 必须是目录内相对路径(拒绝 `..` 与盘符),运行前再做一次包含性检查
- `terminal.shell` 只能是 `powershell/cmd/bash/sh/zsh` 之一,不接受可执行文件路径
- 环境变量限量、限键名、限值长度;任务名去重、总量上限 40
- **读**永不抛异常:非法条目被丢弃并回显原因,一行写错不会让整个项目不可用
- **写**从不降级:保存时 JSON 语法错误或根节点不是对象一律 `400`,磁盘上的文件一个字节都不动
  ——读的容错是为了让项目仍能打开,把它用在写入路径上就变成了「一次手滑把配置换成默认值」;
  字段级的拒绝仍然是 warning,因为那种情况下其余配置确实是用户的本意
- **配置本身不会启动任何东西**,任务只在点击时执行

## 对话可见性与权限

### 一轮回答里能看到什么

服务端把 OMP 的 `AgentSessionEvent` 流按种类转成各自的 SSE 帧,前端按运行时产生的顺序渲染:

| OMP 事件 | SSE 帧 | 对话里的样子 |
|----------|--------|--------------|
| `message_update` · `text_delta` | `delta` | 正文 |
| `message_update` · `thinking_delta` / `reasoning_delta` | `reasoning` | 可折叠的「思考中…」块(只有思考、还没有正文时自动展开) |
| `tool_execution_start/update/end` | `tool` | 工具卡片(参数、输出、差异);输出已去 ANSI、应用 `\r` 覆盖 |
| `auto_compaction_*`、`auto_retry_*`、`retry_fallback_*`、`model_changed`、`thinking_level_changed`、`notice`、`todo_reminder` | `notice` | `·`(信息)/ `!`(警告)前缀的等宽小字 |
| `agent_end` 且末条助手消息 `stopReason: "length"` | `notice`(警告)+ 诊断中心 | 明确说明回答在输出上限处被截断 |

两个曾经的「静默失败」由此消失:

- **一大段空白**:一个 agent 步骤的可见文本往往只有 `"\n\n"`(思考在 thinking 部分,动作在 tool call 里)。逐字拼接会让每个步骤留下一个空段落,多步之后正文前就是一片空白。现在纯空白增量在消息还没有可见内容时被丢弃,段落之间的连续空行归一到一个,模型真正写的空行不动
- **读完文件就不动了**:输出预算耗尽时消息以 `stopReason: length` 结束,既没有正文也没有下一个 tool call,agent 循环随之结束。根因是所有模型共用 8192 的输出上限;现在按模型族给足(见下),并且真的撞上时会说出来

### 输出预算

`max_output` 取两个约束的较小者:模型族的文档值(gpt-5/codex 128K、claude 64K、gemini 64K、o 系列 100K、gpt-4o 16K、gpt-3.5 4K、未知族 32K)与**上下文窗口的 1/4**。后者保证输出不会把提示词的空间吃掉——200K 窗口的 claude 拿到 50K,128K 窗口的未知模型拿到 32K,窗口很小时不低于 8192。

这个值是推导出来的、不是实测的,所以每次启动都会按当前规则重算一遍(`refreshMaxOutputs`):旧版本存下的 8192 不会永远跟着路由。上游报 context 超限而下调窗口时,输出上限一同下调,窗口份额的约束始终成立。

### 权限(是否启用 full access)

OMP 的 RPC 协议**没有**权限开关(见 `rpc.md` 的命令表),宿主唯一能插话的地方是扩展 UI 子协议里的 `confirm` 问句。所以这里只有两档,含义严格限定在「是否弹窗询问」:

| 档位 | 行为 |
|------|------|
| `ask`(默认) | 运行时请求确认 → 弹窗,回答前不继续 |
| `full` | 本机立即回 `confirmed: true`,运行不中途停下;对话里留一行「已自动允许:<标题>」 |

- 判定是一个纯函数(`shouldAutoApprove`):自动应答器与 SSE 转发器在同一次同步事件里对同一帧各自求值,因此无需共享「哪个 id 已经答过」的状态就必然一致
- `select` / `input` / `editor` 三类对话**永不自动应答**——它们要的是内容,替用户编一个答案不叫批准
- 自动应答器在任何 SSE 客户端能连上之前注册,所以它总排在转发器前面:不会出现「转发器跳过了弹窗、而运行还在等」的空等
- 切档不影响 AI 能碰的范围:文件仍受工作区目录的包含性检查约束,预览/任务/终端仍只在显式操作时启动

## OMP 配置

安装后的首次启动会自动使用官方仓库 `can1357/oh-my-pi` 下载 OMP,无需用户配置。
以后每次启动会立即检查一次,运行期间每 10 分钟继续检查 Release 并自动更新。也可显式设置
`OMP_GITHUB_REPO=can1357/oh-my-pi`;其他仓库会被拒绝。桌面版会沿用 Windows 系统 HTTPS
代理,服务端/Docker 也支持标准 `HTTPS_PROXY`、`HTTP_PROXY` 和 `NO_PROXY` 环境变量:

| 通道 | 行为 |
|------|------|
| fast(默认) | 首次安装立即执行;后续版本发布约 15 分钟后自动安装 |
| stable | 延迟 24 小时 |
| experimental | 立即安装 |

版本布局:`/data/omp/versions/<tag>/`,`current`/`previous` 链接切换。
安装前强制校验版本标签和 64 位 SHA256(含已有缓存)。未登录时安装后执行 RPC 握手;
已有模型路由时继续执行 set_model 和真实 prompt。失败自动回滚并复测 previous。

### 启动预算(RPC 握手)

握手的 ready 等待曾经是写死的 10 秒。那个数字是在原生机器上量的,遇到第一台不是原生
的机器就成了 bug:x64 主机上 QEMU 模拟的 arm64 镜像要更久才发出 `ready`,健康事务先把
一个只是慢的进程停掉,容器于是一边回 `/health` 一边带着死掉的运行时。

现在预算按机器推导(`apps/server/src/omp/startupBudget.ts`)。让更宽的天花板变安全的
不是那个数字,而是先把「坏」和「慢」分开:子进程 `exit`/`error` 会**立刻**结束 ready
等待,所以坏二进制仍是毫秒级失败,更宽的上限只由「活着但还没说话」的进程付。

| 画像 | 判定依据 | ready | get_state |
|------|----------|-------|-----------|
| native(默认) | 内核架构与 `/proc/cpuinfo` 一致 | 20 s | 5 s |
| emulated | 内核报 arm64 而 `/proc/cpuinfo` 是 x86 字段(qemu-user 不改写该文件) | 240 s | 30 s |

`get_state` 始终是独立且短得多的超时——启动慢不能掩护 RPC 循环卡死。
可用 `OMP_STARTUP_PROFILE=native|emulated|auto`、`OMP_READY_TIMEOUT_MS`、
`OMP_STATE_TIMEOUT_MS` 覆盖,但**覆盖同样过夹紧**(ready ≤ 600 s、get_state ≤ 120 s):
任何配置都不能把握手退回成无界等待。

实测的 spawn→ready 及其 p50/p95 在 `/api/omp/status.startup` 里,调整上述数字应当引用
它,而不是猜。多架构发布门禁:`ci/verify-docker-omp.sh linux/arm64`——它断言
`running:true` 且 `protocolError:null`,明确不把 `/health` 或 `omp --version` 当作通过。

## 安全设计

- 密码只用于单次登录请求,不落盘、不写日志
- 会话/Key 密文存 SQLite(AES-256-GCM),密钥在 `data/secrets/master.key`(0600)
- 日志自动遮盖密码、Cookie、Authorization、`sk-` Key;任务与终端捕获的输出同样走脱敏
- 所有监听仅绑定 127.0.0.1;Docker 端口映射同样只绑回环
- 控制面强制回环 Host 与同源 Origin;凭据代理使用每进程 256-bit capability 并绑定当前模型
- 分组切换记录 `session_routes`,旧会话保留原路由,避免账单混淆
- **执行类功能(预览命令模式、任务、终端)的一致姿态**:只在用户显式操作时启动;
  客户端只能指定已加入工作区的目录与已声明的任务/脚本,不能传入命令行;
  项目内的 `.botcf/config.json` 按不可信输入校验(参数字符集、参数个数、相对 cwd、shell 白名单);
  所有子进程按进程组/进程树结束,并在 SIGINT/SIGTERM 与目录移出工作区时统一清理
- **git 操作**:永不经过 shell,路径先做包含性检查再成为 pathspec,拒绝可被当作选项的值;
  提交信息走 stdin;破坏性操作要么需要显式勾选(删除新建文件),要么在已推送时默认拒绝改写历史
