# e2e — 编辑器与它的邻居

`npm run test:e2e`

一次运行会:构建 → 生成夹具(含一个 git 仓库) → 启动本地服务(独立数据目录/端口) →
打开真实窗口 → 把一份「本轮变更」经真实聊天流送进页面 → 按 `spec.js` 逐项断言 →
写 `e2e/last-run.json` → 清理。任一项不通过时退出码为 1。

主体是编辑器;末尾三项覆盖**把文件交给编辑器**的两个面板(Git、诊断中心),它们同样没有
真实浏览器级别的覆盖,而且都收在同一条跨面板信号上。

## 为什么存在

文本面从 `<textarea>` 换成 CodeMirror 6 是为了内存(`docs/perf-gate-2026-08-28.md` §6),
但这次替换带进来三件**没有任何测试**的行为:

- AI 改动画成行装饰(新增 / 改写 / 删除三种,删除那种不占行);
- 左边距的改动条,以及点它会发生什么;
- 超过 1 MiB 的文件拿到的**只读**面。

性能门槛开真窗口、真打字、真切标签,但它只问快慢。单元测试则**故意**停在纯函数上:
CodeMirror 在 jsdom 里每个元素都量成 0 像素,视口计算全是退化值 —— 那种「组件测试」测的
是 stub,而且会绿。

所以缺的不是断言库,是**真实浏览器**。这里复用性能门槛自己的引导代码
(`harness/app.cjs`):同一份构建、同样跑在独立端口与独立数据目录上的服务、同一种 Electron
窗口、同一个页面。区别只在于拿它做什么 —— `e2e/spec.js` 断言,不计时。

## 差异是怎么进去的

`内联`、`差异`、改动条、改动装饰都只对「AI 改过的文件」存在,而这里没有 agent 在跑
(更新器被指向死代理,正是为了不在运行中途装一个)。

`harness/inject.js` 只做一件事:**把上游伪造掉,别的都不碰**。它在一次发送期间替换
`fetch`,且**只**替换 `/api/chat/stream` 这一个 URL,回答一段真的 SSE 字节流;消息是打进
真实输入框、用真实回车发出去的。从那段字节往后 —— `streamChat` 的解析、`useChatSession`
的合并、差异解析、按内容重新锚定、行的构建 —— 全是应用自己。

`apps/web` 里没有任何东西知道这个文件存在。如果哪天改动了「差异如何到达编辑器」这条路,
这里会**响亮地坏掉**,而不是靠一个为测试而开的口子继续绿着。

## 夹具

`fixture.cjs` 写两个文件,都是为「能一眼核对」挑的:

| 文件 | 为什么是这个尺寸 |
|---|---|
| `edited.ts`(400 行) | 一屏就能同时放下三处改动;每行写着自己的行号,于是「这个装饰在第 12 行」是**读出来**的,不用把 DOM 位置反推成文档偏移。它同时低于 `FULL_VIEW_LIMIT`,所以内联视图的 `显示全文` 分支在它身上是可达的。 |
| `oversized.txt`(> 1 MiB) | 只有超过 `MAX_FILE_CONTENT_BYTES` 才能拿到只读面:服务端只给有界前缀并标记 truncated,查看器据此以 `editable: false` 挂载 CodeMirror。性能夹具刚好压在这条线**以下**,理由正相反 —— 打不了字的文件量不出输入延迟。两个夹具互相替代不了。 |
| `tracked.ts`(已提交后被改) | Git 面板需要的全部:一个状态已知的文件。**故意不用 `edited.ts`** —— 它的内容必须继续和会话差异的 `+` 行对得上,否则编辑器那几项会连区域都没有。 |

夹具目录本身会 `git init` 并提交一次,身份用 `-c user.email/user.name` 就地给,`commit.gpgsign=false`
一并给上 —— 否则默认签名的开发者机器上,这里会卡在一个永远不会有人回答的口令提示上。
每次运行前先删掉整个目录:上一次留下的仓库里那处改动已经被提交了,面板会正确地显示「干净」。

三处改动的位置(第 6 / 12 / 18 行)不是随手选的:`mergeRegions` 会把相邻的区域折成一个,
而删除区域在它的 start **前一行**结束,所以隔两行的邻居会变成一根条。间距是断言的一部分。

## 检查项

| 检查 | 它盯住的东西 |
|---|---|
| 本轮变更经由真实聊天流送达 | 注入路径本身。后面每一项都依赖它。 |
| 文件头报出正确的改动计数 | `+N −M · K 处` 与生成器的账对得上,且没有一处「无法定位」——锚定坏掉时它会先说话。 |
| 刚送达的改动文件不算「未保存」 | **第一次运行就抓到的那个丢数据的 bug。**内联视图不挂载编辑器,把「没有缓冲区」读成「空缓冲区」会让每个 AI 改过的文件都被标成未保存,并**给它缓存一个空草稿** —— 下次打开就是空文件,一次 Ctrl+S 写回磁盘。 |
| 三种改动各画出自己的装饰 | `cm-region-add` / `-modify` / `-delete` 各一处,且**落在正确的行文本上**。删除那条尤其重要:它画在「原来被删内容所在位置的那一行」上,把那行标成改过会是在说 AI 写了它没写的代码。 |
| 滚出视口再回来,装饰还在原处 | 视口渲染。滚走之后装饰**必须消失**(否则说明根本没窗口化),滚回来必须仍在同样的行上。 |
| 左边距为每处改动画一根条 | gutter marker 的存在,以及每根条的提示是否说得出自己的种类和位置。 |
| 点击左边距的条,跳到内联视图的那一处 | `onSelectRegion` → 切到内联 → `revealLine`。断言目标行**落在可视区内**,不只是存在。 |
| 内联视图把删掉的行显示在原位 | 内联视图存在的理由本身。 |
| `显示全文` 展开省略的区间,而且仍然只渲染一屏 | `buildInlineRows` 的另一条分支:折叠时行数跟着**改动**走,展开时跟着**文件**走 —— 后者正是当年会往文档里塞几千行的形状。断言省略行消失、建模行数变多、而 DOM 里的行数**不到**建模行数的一半。 |
| 超过 1 MiB 的文件只读打开 | `查看 …` 无障碍名、不可编辑、没有「保存」按钮、文件头写明只读预览。 |
| 只读文件拒绝键入 | `EditorState.readOnly` 真的生效,而不只是长得像。 |
| 撤销把缓冲区改回干净 | 换成 CM6 时,浏览器原生撤销跟着 textarea 一起没了;`@codemirror/commands` 的 `history()` 是它的替代。**一个撤销之后不肯消失的 ● 是在谎报未保存的工作。** |
| Git 面板列出工作区里未提交的改动 | 面板把**真实的** `git status` 渲染出来。 |
| Git 面板能暂存一个文件 | 点「暂存」之后条目变成「取消暂存」—— 面板不是本地翻个标志位,而是重新读了一次 git。 |
| 诊断中心收下运行时报错,并能跳到出错的那一行 | `/api/diagnostics/runtime`(沙箱预览页报错走的就是这条)→ SSE 推送 → 面板渲染 → 点「在编辑器中打开这一行」→ 编辑器切到那个文件。**跨面板那条信号**,Git 和审查面板用的是同一条。 |

一项失败会**停下**而不是继续:这些检查是有顺序依赖的(只读文件得先打开才能往里打字),
十几条由同一个原因引发的失败是噪声不是信息。停下来之后剩余项标为 SKIP,报告里看得见跑到
哪一步。面板那三项排在最后,所以编辑器的结果不会被它们盖住。

**git 不可用时,Git 那两项判失败,不是跳过。**没跑过的检查不算通过 —— 和门槛里
`jsHeapRetainedMiB` 答不上来就判失败是同一条规矩。

## 为什么没有审查面板

`审查` 的状态只由**一次真实的 agent 回合**写入(`recordAgentTurn`,只在 OMP 聊天路径上被
调用),没有任何 HTTP 路由能记录一个回合。要覆盖它就得给产品开一条「为测试而存在」的路由 ——
而这套 harness 从第一天起拒绝的正是这个:一个为测试开的口子会在重构之后继续绿着。
Git 和诊断中心之所以能进来,恰恰是因为它们的状态**有诚实的来源**(磁盘上的 git 仓库;
预览页本来就在用的上报端点),不需要为它们改动产品一行代码。


## 边界

- 和性能门槛一样,只在桌面会话里有意义:窗口必须可见且不被节流。
- 端口(7797/7796)与数据目录(`botcf-e2e-data`)都和性能门槛错开,两者可以同时跑。
- 需要 `git` 在 PATH 上;没有的话 Git 那两项会判失败并说明原因,其余照跑。
- 运行期间不联网;用户自己的数据目录和工作区不会被动到。
- `--keep` 保留夹具与临时数据目录,`--json <file>` 改写结果去向,`--no-show` 仅用于排查。
