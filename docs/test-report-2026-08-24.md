# BotCF 软件功能与大型项目性能测试报告

日期：2026-08-24

## 结论

**当前版本不是“功能完全可放心使用”的状态。** 单项目常规编辑、任务、终端、预览、Git、AI 审查和正常路由下的 AI 对话均可工作；但发现 3 个 P1 问题：切换主目录后 AI 路由失配、OMP 错误被吞成空白回答、非法项目配置会覆盖原配置。多大型文件同时编辑还能使用，但有明显输入延迟和较高内存高水位。

建议发布判断：阻止正式发布，先修复 P1；P2 性能问题至少应给出门槛、压测和回归保护。

## 测试对象与方法

- 实际桌面应用：Electron 主进程 + 生产构建的 Web/Server + 本机 OMP v18.0.3。
- 实际界面：通过 Electron 的 CDP 页面执行点击、输入、标签切换、任务、终端、预览、Git、聊天和审查流程。
- 自动化基线：根工作区完整 Vitest；生产 TypeScript/Vite 构建。
- 性能负载：8 个合成大型项目，共 101,248 个文件、27,638,568 字节；每个项目含 12,000 个模块文件、650 个同目录文件、约 950 KB/12,001 行可编辑文本、1 MB 二进制文件和超过 1 MB 的文本文件。
- CPU：桌面完整进程树 CPU 时间，按 32 个逻辑处理器归一化为整机百分比；同时观察 Electron main/GPU/renderer、Node server、OMP 及其子进程。
- 内存：进程树工作集与私有提交量之和。工作集可能包含跨 Chromium 进程共享页；私有内存用于交叉判断。

### 交互延迟

- 单个大型文件：打开 444 ms；短文本输入约 805 ms；保存 149–160 ms。
- 8 个大型标签：切换 628–719 ms；短文本输入 714–904 ms。
- 8 根仅打开、不加载文件时资源开销很小；明显增长来自“每个打开标签都常驻完整 FileViewer”。

## 问题清单

### P1-001 切换主目录后 OMP 活动路由丢失

**复现**：界面选择 `🥺grok-heavy / grok-4.6 / chat` → 把另一个根设为主 → 接口返回 `restarted:true` → 发送短消息。

**结果**：UI 仍显示 grok/chat，OMP 会话却恢复为 `anthropic/claude-opus-4-8`，代理返回 409：`当前路由是 chat 接口,收到的却是 messages 请求`。手动再切一次模型后恢复。

**根因**：`apps/server/src/workspace/service.ts:68-73` 的 `reactivateRuntime()` 只 stop/start/handshake；没有履行 `apps/server/src/appState.ts:110-113` 声明的“每次重启都重应用活动路由”不变量。

**修复**：统一运行时重激活入口：start → handshake → `applyActiveRouteToOmp()` → 校验 `get_state`；主目录切换、显式重启、更新切换都复用。任一步失败不得返回 `restarted:true`。

### P1-002 OMP 终止错误被吞成空白助手消息

**复现**：触发上述 409。

**结果**：OMP JSONL 有 `stopReason:error/errorStatus:409/errorMessage`；UI 只显示空白“助手:”，`/api/chat/history` 只返回用户消息，诊断中心无新增模型错误。

**根因**：`apps/server/src/routes/chat.ts:453-466` 的 terminal `agent_end` 只处理 `stopReason:length`，其余直接 `finish()`；前端只有收到 `type:error` 才追加错误文本。

**修复**：解析最后 assistant 的 error 状态，发送脱敏 SSE `type:error` 并记录诊断；回归 normal/error/length/abort 四类终止。

### P1-003 非法 JSON 保存会破坏现有项目配置

**复现**：保存包含 `CUSTOM_KEEP_ME` 的有效配置 → 保存 `{bad json`。

**结果**：HTTP 200 + warning；磁盘配置已被默认值覆盖，哨兵字段丢失。

**根因**：`parseProjectConfig()` 的“读取时容错为默认配置”被写入接口直接复用；`POST /api/project-config` 无条件保存返回的默认对象。

**修复**：写入路径语法错误返回 400，保持原文件字节和 mtime；仅语法合法后的字段规范化允许带 warning 保存。

### P2-004 多大型标签同时编辑时内存与输入延迟过高

**证据**：8 个 950 KB/12,001 行脏标签，进程树峰值工作集 1,453.4 MiB、私有内存 1,606.9 MiB；短输入 714–904 ms。关闭标签 10 秒不回落，重载后工作集降低约 272 MiB。

**根因**：`apps/web/src/components/EditorTabs.tsx:63-80` 为每个标签始终挂载完整 `FileViewer`；受控大 textarea、全文缓冲和派生计算全部常驻。

**修复**：仅挂载活动查看器；脏草稿/滚动/视图模式存轻量状态；大型文件使用虚拟化或增量编辑模型。建立 8 × 1 MB 性能门槛。

### P2-005 缺少真实浏览器/桌面端到端回归套件

**证据**：现有 736 个 Vitest 全部通过，但仓库没有 Playwright/Electron E2E 配置；P1-001、P1-002、P1-003 仍可端到端出现。

**修复**：加入最小发布门禁：启动 Electron、切换主目录、真实/受控模型 prompt、文件保存冲突、非法配置不落盘、任务/终端/预览/Git 冒烟。外部模型可用本地严格契约服务器覆盖路由类型。

### P3-006 窄任务面板操作按钮逐字换行

**证据**：实际 Electron 截图中约 300 px 宽任务面板的“上次输出”“运行”被压成竖排。

**根因**：共享 `BUTTON` 无 `whiteSpace:nowrap`/`flexShrink:0`，任务 `ROW` 允许动作继续收缩。

**修复**：动作按钮禁止换行和收缩；空间不足时优先省略命令摘要或收起次要动作。

### P3-007 主目录切换后立即重载会短暂显示“0/8 个目录”

**证据**：后端 `/api/workspace` 已返回 1 根，界面初始帧仍显示 0/8 和空路由控件；稍后刷新恢复。

**根因**：初始 state 使用“空工作区”而不是“加载中”；`FileTree` 首次请求失败时没有自动重试。请求是否确实失败本轮未取得网络日志，因此此根因部分为 **[INFERENCE]**。

**修复**：首屏增加 loading/last-known 状态；本地 API 暂时失败时短退避重试，不把未完成加载渲染成真实空工作区。

## 八项质量审计摘要

1. **可读性**：模块和关键安全不变量注释充分；问题定位路径清楚。
2. **模块化与维护性**：运行时重启逻辑分散，未共享“重应用活动路由”不变量，是 P1-001 根源。
3. **性能**：目录和文件读取均有上限；编辑器多标签常驻导致 P2-004。
4. **错误处理与鲁棒性**：文件冲突/越界/会话上限处理良好；模型终止错误和配置写入错误处理不合格。
5. **安全性**：实测工作区越界、Git 越界、二进制/超限保存、终端会话上限均正确拒绝；本轮未重做更新供应链与 LAN 暴露审计。
6. **测试覆盖**：单元/契约覆盖数量高，但缺真实桌面 E2E 和性能门槛；全部单测通过仍漏 3 个 P1。
7. **一致性与风格**：构建、脚本和服务接口一致；任务按钮在 Dock 最小宽度下不符合既有可读性标准。
8. **文档完整性**：README 功能说明详细；“切换主目录后正常继续 AI”“错误可见”“配置绝不静默丢弃”与实测存在偏差，应在修复后补验收说明。

## Lessons learned / 预防规则

1. 运行时重启不是 handshake 完成；必须恢复并校验业务路由后才算可用。
2. “读取坏配置时降级”与“保存坏配置”是两套语义；写入失败绝不能覆盖最后一份有效数据。
3. 终端错误必须形成用户可见结果；空助手消息不得作为 error 的正常表示。
4. 多标签保持状态不能以常驻所有完整编辑器为代价；状态保存和视图挂载应解耦。
5. 单元测试全绿不能替代 Electron 端到端冒烟；主目录切换、模型调用和配置落盘必须进入发布门禁。
6. Dock 组件必须在最小尺寸和 100%/150% 缩放下截图验收。
